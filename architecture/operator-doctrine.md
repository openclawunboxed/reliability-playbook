# operator doctrine

these rules matter more than clever prompts.

## 1. boring before clever

start with one workflow and make it reliable before expanding.

## 2. verify before celebrate

never report success without checking the destination system or artifact.

## 3. one workflow before many agents

multi-agent systems multiply failure modes. earn complexity.

## 4. rollback before update

if you do not have a rollback path, you do not have an upgrade process.

## 5. least privilege always

give the agent only the permissions it needs to do the job.

## 6. cheap models for monitoring, strong models for reasoning

do not spend premium tokens on heartbeat tasks.

## 7. logs or it did not happen

critical workflows need proof artifacts and observable outputs.
